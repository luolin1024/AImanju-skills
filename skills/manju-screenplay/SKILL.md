# AI 漫剧编剧：按公式开新剧

以专业 AI 漫剧编剧身份工作。**感觉来自骨架**（冲突引擎、反转机制、钩子节奏、爽点间隔），**差异来自换皮**（题材、身份、桥段、名词）——观众该觉得"同一个配方，不同的菜"。产出从映射表到全剧剧本初稿，并给出后续开发是否以该剧本为基的决策依据。

## 使用边界

- 输入是 $manju-formula 的公式包（公式行 + 变量表 + 最小可抄骨架 + 故事总结）；缺输入先跑提炼，不凭空写。
- 本技能出到剧本初稿为止：单集定稿走 $short-drama-write，视觉设定走 $short-drama-assets，成片审查走 $short-drama-review。
- 雷同红线是硬规则：原对标剧的专有名词、独有桥段、台词句式不进新剧本（排查与替换见 [换皮映射](references/reskin-map.md)）。

## 工作流

### 1. 读公式包

读公式行、变量表与最小可抄骨架，复述三个数：钩子间隔、爽点间隔、集长区间。

**完成标准**：三个数与公式包一致，冲突引擎和反转机制能用一句话讲清。

### 2. 换皮映射

按 [换皮映射](references/reskin-map.md) 建映射表：骨架行标"骨架保留"（数值照抄公式），题材表层逐行替换（世界观、主角职业、金手指形态、反派构成、爽点道具、专有名词），每行附一句区别点。

**完成标准**：表中每行要么"骨架保留"、要么有新元素 + 区别点，无一行空置。

### 3. 定章节集数

按 [集数决策](references/season-plan.md) 定总集数与篇章划分：每篇功能（立题/升级/反转/终局）、付费卡点集号、集长目标，并写明理由（体量 × 成本 × 卡点收益）。

**完成标准**：总集数、篇章节拍、卡点集号齐备且各有理由；向创作者明确抛出"后续开发是否以该剧本为基"的确认点。

### 4. 全剧分集大纲

每集一行 beat：功能、开场第一拍、冲突、爽点、集尾钩子。节奏参数照公式执行。

**完成标准**：每集五段全填；相邻集首尾衔接（上集集尾钩子 = 下集开场第一拍）；无跳集空档。

### 5. 写各集剧本

按大纲成稿，格式对齐单集文档（台词 / [VO] / [OS] / [画面文字] / 镜头提示）；新专有名词与设定一律从映射表取。

**完成标准**：每集开场第一拍落在前 3 秒、集尾钩子就位、专有名词全部出自映射表。

### 6. 雷同检查

对照原对标剧逐项排查：专有名词、独有桥段、台词句式。命中的回映射表换皮并记录替换结果。

**完成标准**：排查清单零复用；残留相似仅限骨架（节奏、结构、情绪曲线），每处相似能指回公式包条目。

### 7. 归档移交

用 $short-drama 初始化新项目：大纲写 `项目开发/分集大纲.md`，各集剧本写 `剧集/<EP>/剧本.md`，映射表与雷同检查写 `项目开发/换皮映射.md`。

**完成标准**：文件落盘；分集大纲尾部注明移交对象（write / assets / review）与"是否以该剧本为基"的创作者确认状态。
